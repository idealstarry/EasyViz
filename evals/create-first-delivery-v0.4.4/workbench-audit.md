# Workbench request-flow audit for 0.4.4

Checked on 2026-10-05. Scope: `figure_workbench.py`, `apply_figure_requests.py`, `workbench/workbench.js`, and their request-flow tests. Create candidate generation remained frozen; no UI appearance changes were made. This report records reproduced correctness failures and focused verification, not a blanket security or aesthetic certification.

## Reproduced failures and fixes

### R1 — A successful request from another Workbench instance could disappear

Before the fix, the queue-byte comparison occurred before `write_ledger()`. Each instance had its own Python thread lock, so that comparison did not serialize a browser server with another server/CLI process. In the reproduced interleaving, instance B successfully saved a request after A's last comparison but before A's file replacement. A then replaced the queue using its older snapshot. B's returned request ID was absent from the final ledger (`request_b_silently_missing: true`). Numbered opinion 2 could disappear while opinion 1 reported successful publication.

The fix uses a bounded OS filesystem lock shared by all cooperating processes, snapshots bytes and parsed ledger together, and checks the expected bytes/figure version inside the lock immediately before atomic publication. A stale writer receives a conflict without removing B's request; retry saves the remaining number. The lock inode remains in place, with kernel ownership released on process exit, so a leftover file does not become a permanent stale lock. Symlinks and nonregular lock files are rejected; temporary queue files are created exclusively, flushed, synchronized, replaced atomically, and cleaned up. No process-global lock cache is used.

Real tests cover a late independent-instance mutation through HTTP, an independent subprocess holding the OS lock while publishing a request, a second writer waiting and rejecting its stale snapshot after release, bounded contention, process termination with the persistent lock file still present, and a symlink lock target that remains byte-identical. Original source and export files remain byte-identical in the late-window test.

### R2 — Failure while recording into the target attempt left the source irreversibly applied

Before the fix, `record_requests()` wrote the source ledger first and the merged target ledger second. A reproduced target write error left the source request marked `applied`, while the target had no application history. Retry failed with “Only pending requests bound to the current figure version may be processed”. This was an actual partial history update, not an invalid-input test.

The fix locks both attempts in stable path order, compares both captured queue snapshots under those locks, and restores both previous byte snapshots after an ordinary publication failure. Rollback failures are reported explicitly as incomplete recovery. The regression injects a failure **after** the target's atomic replacement, verifies both ledgers return byte-for-byte to their previous state, then retries successfully. The target's independent pending request is retained, and both attempts record the same successful event ID. A separate late target-request injection is rejected before either ledger changes.

Acceptance now also publishes its history under the shared lock. An ordinary failure rolls back the ledger and removes only the snapshot created by that operation, making acceptance retryable. Its regression injects failure after the ledger replacement, checks the pending numbered request survives and no partial accepted snapshot remains, then confirms one successful acceptance history event on retry. Prepare and restore history publication also use guarded writes; restore merges any independently saved target instructions.

### R3 — Restored focused exports still declared the changed original input in settings

The original reproduction rendered real focused replicate bars, accepted them, changed the original data/spec, and restored the accepted bundle. `elements.json.input` pointed at the restored files and Workbench reported `source_current: true`; however, `settings.json.input_file` still pointed at the altered original CSV. `create_review.source_bindings()` consequently reported a failed settings input binding. The original reproduction was retained under the temporary directory `easyviz-workbench-restore-proof-8rbbzs_j`.

Restore now rebinds declared nested and direct settings source/data/spec pointers to the frozen restored files. It preserves direct absolute-versus-relative path form, all hashes, scientific settings, layout, typography, and the accepted export bytes. The new end-to-end regression renders actual SVG/PDF/PNG with the focused replicate renderer, accepts, mutates original data/spec, restores, and checks every declared data/source/spec claim with the independent Create review binding reader. All restored claims pass and point inside the restored bundle. Settings differ only in the input pointer; SVG/PDF/PNG, plotting data, and statistics remain byte-identical.

### R4 — QA could invalidate after its early check while history still published successfully

The independent reviewer subsequently reproduced two missing publication guards (original review and exact diagnostic outputs remain in `workbench-fix-review.md`, unchanged by this owner). The record probe changed only target QA to `needs_revision` before the shared locks; the source request still became `applied`. The accept probe changed QA to `in_progress` after the first read, before bundle capture; the accepted snapshot itself contained `in_progress` QA. Queue serialization alone did not bind the technical evidence used for acceptance/application.

`record_requests()` now captures the actual QA bytes and stores their hash in the application event and request result. It compares those bytes under the shared locks before, between, and after the two ledger publications. Passing status is also revalidated. A drift after publication triggers the existing byte-exact rollback of both ledgers. `accept_attempt()` validates the QA actually captured in its bundle, requires it to match the early QA bytes, checks the written snapshot's actual QA and current QA before history publication, and checks current QA after publication. Failures preserve the original pending queue and remove only the partial snapshot from that failed operation. Acceptance metadata/history now records the QA hash. Merely obtaining a newer `pass` status does not silently substitute different QA bytes in an in-flight operation.

If `valid_outputs` is declared it must be the JSON boolean `true`; `false`, `0`, `null`, and the string `"false"` are rejected. An entirely absent field remains compatible with legacy QA. When `QA.exports` declares a per-format `sha256`, record checks the target's actual SVG/PDF/PNG/TIFF bytes, and accept checks both the captured/written snapshot and the actual current exports. The QA bytes are read again after the live export checks to detect renderer invalidation during those reads. Existing hashes are the authority; legacy formats without declared hashes do not acquire a claim of proven export binding.

Two new regression methods execute 18 controlled scenarios: record invalidation before the lock, after the source publication, after the target publication, and changed still-passing bytes; accept invalidation before capture, immediately after capture, before publication, after publication, corrupted written snapshot QA, and changed still-passing bytes; plus the four explicit invalid flags for each operation. Every failed case preserves prior ledger bytes and remains successfully retryable once valid original QA is restored. A third regression uses actual core SVG/PDF/PNG/TIFF exports: replacing only PDF or TIFF with a different valid exported figure while leaving QA and semantic version unchanged rejects both record and accept. Replacing live PDF after snapshot capture also rejects acceptance and cleans the partial snapshot. Restoring matching export bytes allows retry, with QA hashes and accepted export hashes checked against the actual files.

## Checked request and security boundaries

Source review and existing executed tests covered numbered batch atomicity; individual selection identity and property restrictions; permanent number reservation across undo/applied statuses; stale source/spec/export/semantic-map rejection; pointer escaping; finite numeric values; immutable export geometry; fixed physical region bounds; source hash checks; and accepted bundle tampering/path/symlink rejection. The client harness exercised separate per-number drafts, switching/removal, failed batch retention, same-version refresh, version isolation, number reuse rules, and keeping annotations bound to the viewed SVG when queue/state responses describe newer geometry. No further concrete incorrect-target or client request-loss defect was reproduced in this scoped review.

The local server binds `127.0.0.1` and checks the exact Host. Mutations require the exact local Origin and a random session token. Paths and downloadable files are allowlisted; figure file reads are bounded and reject symlinks. CSP and no-sniff headers are emitted. Preview SVG sanitization removes active elements, event attributes and external references, while original downloads retain their exact bytes. Executed negative tests covered remote Origin, rebinding Host, missing session token, traversal/unsupported payload fields, active SVG content and nonfinite JSON. These are verified controls for the tested inputs, not an exhaustive penetration test.

## Limits

The OS lock and process-death tests ran on macOS/POSIX; the Windows `msvcrt` branch was reviewed but not executed here. External writers that ignore the shared lock, local malicious processes replacing lock inodes, and unreliable remote-filesystem lock implementations are outside these cooperative writer guarantees. Dual-ledger rollback handles ordinary Python/filesystem failures; it is not a two-file crash transaction or a write-ahead journal, so abrupt process termination/power loss between two file replacements still requires explicit recovery. QA/export guards bind the bytes observed during publication; they do not prohibit an external renderer from changing an attempt after the operation returns, and absent legacy export hashes cannot prove old format measurements apply to actual PDF/TIFF bytes. No real-browser UI session or general network fuzzing was performed for this audit; the client evidence is the executed Node harness. No author plotting script was executed by the Apply/Restore helper.
