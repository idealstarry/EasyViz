# Independent critique of design value

The previous benchmark supports bounded layout correctness. It does not establish a visual improvement across its feasible cases, or demonstrate the design value of EasyViz. I opened the original images listed below in before/after pairs at matching exported dimensions, rather than judging only the contact sheet. These are visual judgments, not a physical print proof.

| Finding | Specific evidence | Consequence |
| --- | --- | --- |
| A fitting legend can become a competing heading. | In `legend-transfer/cases/categorical-8-long-180/after/panel.png`, the eight long category names now form a dense two-row banner wider than the data axes. Before clips the right-hand labels, so a repair was necessary; moving all text to the top solves clipping but makes that text the most prominent structure. | Classify this as a fit repair with unresolved hierarchy, not an unqualified aesthetic improvement. Compare different positions or a deliberate data/legend layout before acceptance. |
| Compaction sometimes relocates whitespace rather than improving the panel. | In `dot-small-88` and `colorbar-square-88`, after shortens the colorbar and packs guides near the top, but the plot rectangle and reserved right margin are unchanged. In `manual-categorical-132/after/panel.png`, the small key floats well above and left of the data rectangle in otherwise empty canvas. | Occupied guide area is not a quality score. The manual case proves an override, not good automatic placement. Preserve an already balanced before when a smaller guide does not help reading. |
| Some spacing changes are genuinely useful, but modest. | In `categorical-8-short-180`, after removes the conspicuous default gap between dots and G1–G8 labels. In the cell-atlas case, the after footer is substantially shallower and row spacing increases while physical font and data mappings remain stable. | Keep these improvements. They are useful typography/layout maintenance, not evidence that a general scientific design problem has been solved. A blanket rollback would also discard benefits. |
| A richer real-data example has a more consequential unresolved encoding problem. | `examples/create/annotated-inhibition/panel.png` shows a mostly pale coral matrix beside highly saturated cyan summaries. Its 400 displayed measurements have quartiles 79.19, 139.28 and 200.66 min, against a −400 to 1000 color scale; values range from −51.71 to 961.51. The colorbar labels −400, 300 and 1000 omit zero. The current image makes modest matrix differences and the sign change hard to inspect, while the summaries command attention. | Evaluate the scientific role of zero, range comparability, and whether a different continuous normalization or sign-aware color scale helps the intended reading. Preserve numeric data and record any normalization change. Increasing the number of decorations would not solve this. |
| The challenge inputs largely predetermine the design. | The legend cases use tiny regular synthetic scatter patterns, a 5 × 5 dot matrix and small heatmaps with generic labels. The richer forest request already prescribes chart type, ordering, grouping, colors, point style, interval treatment, physical size and typography. Those examples mostly ask the agent to execute specifications. | They are valid renderer tests. They do not test whether the Skill chooses an informative structure from an under-specified scientific request, recognizes a misleading default, or improves information hierarchy on unfamiliar source data. |
| Previous acceptance language exceeds the evidence. | `legend-transfer/visual-review.md` calls all nine feasible after panels “visually ready” and says there is no minor visual defect, while its findings primarily establish legibility, clipping and collisions. The code/data checks and immutable area mappings are useful and remain valid. | Retain technical pass statuses, but withdraw aesthetic superiority and Skill-value conclusions. Future design acceptance should identify an actual reading task made easier, compare alternatives on identical data and final size, and allow “before is better” or “no material gain.” |

The next demonstration should use one substantial existing source dataset and a minimally specified scientific reading task, then record the decisions EasyViz contributes: hierarchy, ordering, encoding, uncertainty, and physical layout. A held-out dataset should exercise those decisions afterward. More layers are justified only when they convey additional relevant information. Keep the agreed font sizes, omit overall titles/prose inside the panel, preserve source data, and export one final-size panel.
