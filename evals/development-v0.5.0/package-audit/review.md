# Packaging and installation audit

The packaging/install changes are ready for the release coordinator's final whole-repository checks. No commit, tag, release or live installation was performed in this scope.

## Actual defects repaired

- Case sync previously deleted all generated cases before reading the full source set. A later missing/invalid source could leave half a package. Sync now prepares a complete candidate, checks all owned destinations, then replaces only the 18 generated case directories and two recipe files with rollback. Hand-maintained recipes, fixtures and other siblings remain intact.
- Sync could follow source file or directory links outside the repository and materialize external bytes into ordinary package files. Source directories must remain owned; file links can resolve only to regular files inside the repository. The two existing shared legend-helper links continue to work. Special files and cyclic links fail before actual assets change.
- Build previously removed the old build tree and overwrote the archive before copy/ZIP generation succeeded. It now stages the complete package, validates resources and Markdown before publication, checks that the copied manifest equals the initial manifest, and publishes the tree/archive/summary together with rollback. A rollback failure retains its original recovery bytes rather than deleting them.
- A real ZIP with a corrupted later member was reproduced: the previous extractor overwrote an earlier existing README before reporting its CRC failure. Complete staged decoding now precedes enumerated leaf publication. Existing unrelated files survive, and replacing an existing hard link no longer writes through to its external inode. All normalized-path, special-file, symlink, count/size-budget and conflict checks remain in place.
- Failed catalog writes could leave a partial temporary file. The write/cleanup lifetime now covers the actual write. Isolated installation catalogs now preserve unrelated entries and metadata, refuse a catalog belonging to another installation, and restore the EasyViz entry on CLI failure.

## Compatibility and portable resources

Old core-only manifests remain installable. Version 0.5.0 requires `analysis_result.py` and `figure_service.py`; an optional MCP adapter/requirements file requires its complete local adapter/service/requirements closure. Packaging does not activate MCP or add the optional SDK to core requirements.

`scwat-broken-axis` ships its 17 curated code/input/reference/frozen-preview/data files. Current-path settings, QA, artist maps, consumed-input receipts and development histories are deliberately regenerated by fresh local drawing rather than shipped as current claims. Existing public reset/extraction/install interfaces remain available. Duplicate extracted-source probe logic was consolidated without dropping the actual subprocess/source checks. The obsolete destructive build path/second count walk and an isolated-catalog read overwritten before use were removed. Shared README rewrites are constants; three custom prose files are no longer copied before being read/transformed/written again. No remaining unreferenced private helper was proven obsolete; sparse callers did not justify removing the public reset interface.

## Verification and measurements

- All 84 focused build/sync/extraction/resources/rollback/installer checks passed. They include late invalid input, partial copy and ZIP failure, post-replacement publication failure, actual late ZIP CRC corruption, external/special/cyclic source links, a hard-link target, catalog rollback and recoverable rollback failure. A final isolated sync-module run also covers the added cyclic-link branch.
- `structure-smoke.json` records a real temporary 0.5.0 build and extraction with 946 files, complete resource/Markdown validation, exact archive identity, and a fresh copied/extracted DejaVu Sans segmented-axis redraw through the explicit public `--font` override. Actual SVG/PDF checks retained 60 observations, 12 summaries, 92 × 66 mm size, actual 8 pt PDF text, embedded/editable fonts, 162 mapped elements and eight current consumed roles. The canonical Arial 8 pt spec/PNG/PDF/SVG bytes stayed identical before/after the portability run. Optional MCP `--help` succeeded with `-I -S`, with no site-packages or SDK. This is portability/numeric evidence, not an aesthetic review or MCP protocol-session claim.
- `benchmark.json` was recorded before adding the 18th case. Its equal 654-file / 17-case refresh measurement showed 1.42 s versus 1.55 s median over three local traced runs, including identical tree-identity checks. The safety/staging overhead was about 0.14 s. The benchmark script identifies any later added cases explicitly so reruns do not mislabel unequal work as a pure timing improvement.
- For the actual 18,703,087-byte 0.4.6 archive, whole-file hash allocation peaked at 18,707,928 Python bytes and chunked hashing at 2,102,478 bytes; the digest was identical over seven trials. Medians were 7.43 ms and 7.67 ms. The improvement is bounded memory, not a claimed speed gain. Build also counts archive files in its existing ZIP walk rather than traversing the copied tree again.

Publication uses individual filesystem renames plus rollback on caught failures. It does not assert that a group of file replacements is one global filesystem transaction or that forced process termination can execute rollback. Previous assets are retained in controlled staging if restoration itself fails. Final release verification must use the coordinator's final source bytes, since other modules and the new case were developed concurrently.
